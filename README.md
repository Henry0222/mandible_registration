# Mandible Registration

**口扫与 CBCT STL 的下颌位姿传递、髁突位移分析和三维测量工具。**

[![Version](https://img.shields.io/badge/version-1.0.0-1769aa)](https://github.com/Henry0222/mandible_registration)
[![Python](https://img.shields.io/badge/Python-3.11--3.13-3776AB?logo=python&logoColor=white)](https://www.python.org/)
[![License](https://img.shields.io/badge/license-BSD--3--Clause-4c8c2b)](LICENSE)

Mandible Registration 是一个面向个人研究和几何验证的 Windows 桌面应用。它把两个时间点的上下颌口扫、CT 全牙列和下颌骨组织成固定的六 STL 工作流，通过三阶段刚性配准将口扫中的下颌位姿变化传递给 CT 下颌骨，随后提供阶段复核、髁突中心位移分析以及跨骨距离和角度测量。

本仓库包含源代码、测试和 Windows 便携版构建配置，**不包含患者数据、口扫或 CBCT/STL 测试文件**。程序只读取输入模型，不覆盖原始 STL。

> [!WARNING]
> 本项目仅用于研究、学习和个人几何分析，不是医疗器械，不提供临床诊断或治疗决策。数字咬合、扫描、分割、选区和配准误差都会传递到最终测量结果。

## 主要功能

- 连续选择或拖入六个 STL，并以动态 SVG 流程图显示输入和配准状态。
- 自动完成 CT 牙列定位、两次上颌对齐和下颌位姿变化三个刚性配准阶段。
- T_CT 多随机种子一致性检查，质量未通过时停止矩阵向颌骨传播。
- 可选的牙面重点选区、左右或单侧髁突面片选区。
- 阶段彩虹图、八模型显隐、XYZ 方向视图和模型颜色控制。
- 两次下颌骨间的距离、角度、髁突中心位移与刚体旋转分析。
- 保存 4×4 变换矩阵、模型哈希、质量指标和可追溯的 JSON 结果。
- PyInstaller onedir 便携版，无需目标电脑安装 Python，也不依赖父目录源码。

## 六 STL 输入与配准流程

程序依次使用：

1. 下颌口扫.1
2. 上颌口扫.1
3. 全牙列（CT 转 STL，可同时包含上下颌牙冠和牙根）
4. 颌骨（CT 转 STL）
5. 上颌口扫.2
6. 下颌口扫.2


三个刚性配准阶段为：

```text
T_CT    = Reg(全牙列 -> 下颌口扫.1)
T_UPPER = Reg(上颌口扫.2 -> 上颌口扫.1)
T_DELTA = Reg(下颌口扫.1 -> T_UPPER * 下颌口扫.2)

颌骨.1 = T_CT * 颌骨
颌骨.2 = T_DELTA * T_CT * 颌骨
```

所有变换均为毫米坐标中的 4x4 刚性矩阵，不估计缩放或非刚性形变。

核心配准通过已安装的 `general-model-registration==2.0.0` 公共接口实现；源码运行时不直接导入父目录，Windows 便携版已经包含所需运行依赖。

## 配准可靠性与限制

第一阶段默认不要求人工选择牙面片。CT 上下颌牙列可以保持为同一个 STL，算法按局部重叠完成 CT 牙列到下颌口扫.1 的定位；若自动结果不稳定，也可分别在“下颌口扫.1”和“全牙列”节点点击“选区”，为 T_CT 指定重点采样面。

`T_CT` 会至少使用两个不同随机种子计算。只有两次均达到覆盖、法向一致性和残差门槛（参考面覆盖率 ≥ 0.25、法向一致率 ≥ 0.70、P90 ≤ 0.80 mm），并且两个刚性矩阵之间相差不超过 2°/2 mm，矩阵才允许传递给颌骨；否则继续寻找一致解，最多五次。五次仍不一致时流程停止，保留最佳候选用于彩虹图检查，但不会传递给颌骨。每次尝试和两两差异均保存在 `stages` 目录。覆盖率来自几何匹配，并不是牙冠分割掩膜。

应用在加载 Open3D 前固定 OpenMP/BLAS 线程数为 1，减少并行 RANSAC 中仅设置随机种子仍无法复现的问题；这只影响本程序进程，不修改系统环境或通用配准项目。运行耗时可能增加。几何质量与一致性门槛没有放宽，固定计算顺序也不保证所有数据都能正确配准。

## 运行图形界面

主界面以一张连续的 SVG 流程图展示模型依赖，不再拆成三个面板：左侧用上颌统一口扫坐标，中间为共享 CT 原始坐标的全牙列和颌骨，上方定位颌骨.1，下方传递下颌位移生成颌骨.2，最右侧汇总到“对比 / 测量”。输入节点可点击选择 STL，也可单文件拖入；红叉和浅灰文字表示暂缺，绿勾和黑字表示已导入。派生模型节点在配准产生对应结果后变为绿勾，不能作为输入上传。右键输入节点可更换或清除该项。流程图调整不改变实际三阶段计算顺序和矩阵传递。

“导入 / 补充 STL”打开一个持续显示的文件浏览窗口。按上述顺序确认文件，浏览窗口保留目录并自动切换下一项，不要求文件使用固定名称。可拖入当前步骤文件，使用“上一步”修改、“暂缺，跳过”跳过缺失项，或随时“保存已选项”返回主界面。取消不改变主界面原有选择。部分选择仅保留在本次程序会话中，尚未保存为项目；**允许部分导入，但六项齐全前不能开始配准，不运行部分阶段**。已选项可以再次打开此窗口补齐。

多个 STL 同时拖入流程图会打开用途确认窗口，不依赖资源管理器的选中顺序。约定测试文件名和新的简短名称（例如 `下颌口扫.1.stl`）可自动匹配，其他名称需确认用途。文件不会移动或修改；非 STL、重复文件及网络链接会被拒绝。颌骨节点的“选区”用于左右髁突测量；下颌口扫.1和全牙列节点的“选区”用于 T_CT 重点面。配准中禁止修改输入、选区和结果目录。

“结果位置”地址栏可输入地址，直接拖入文件夹，或拖入文件以使用其所在文件夹。点击“开始配准”运行。详细进度和诊断日志折叠在“运行详情”中。

每个阶段的粗汇总线按照质量状态显示绿色（通过）、橙色（需复核）或红色（未通过）；点击粗线或其下方文字打开该阶段的配准彩虹图。失败候选明确标记为“仅供检查”，不会生成颌骨传递结果。灰色表示未运行，蓝色表示运行中。已完成项目可通过“打开已有结果”重新载入流程图，无需重新配准。

### 调整 SVG 流程图

可编辑图稿是 `src/mandible_registration/assets/workflow.editable.svg`，保留原生文字、节点、连线和语义 ID。`flow_diagram.py` 用 `QSvgRenderer` 渲染它，根据导入与配准状态在内存中更新图标透明度、文字颜色、粗线颜色和提示；Qt 处理点击及拖入，SVG 中不执行 JavaScript，也不需要浏览器。运行不会把状态写回图稿。结果节点“对比 / 测量”在两次颌骨都生成后可点击。

修改布局、字号或文字时保留各元素的 `id`、`data-key` 和 `data-kind`。阶段连线通过固定 ID `stage-T_CT`、`stage-T_UPPER`、`stage-T_DELTA` 关联功能；`data-stage` 建议保留，但编辑器丢失它不会再导致阶段失效。连线支持 `<polyline>`、`<line>` 和 Inkscape 的 `<path>`，包括直线、贝塞尔曲线和弧线；绘图与点击区域使用同一几何数据，父组平移等变换也会应用到点击坐标。

程序更新状态时会同步处理 Inkscape 内联 `style`，避免固定的灰色覆盖动态绿/橙/红，同时保留原有线宽、字体等样式。文字保持 `<text>`，不要转曲或合并成图片；不要把整组控件合并成一个路径。更改图稿后重启软件。导入窗口的角色名称定义在 `models.py`，如需改名须同步更新该处。编辑前的用户原稿保存在 `assets/backups/`，运行时只读取 `assets/workflow.editable.svg`。

## 源码运行与开发

本项目通过正式 Python 包依赖通用配准核心，不读取相邻父目录源码。当前需要先取得并安装 `general_model_registration-2.0.0-py3-none-any.whl`，再安装本项目：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install `
  "C:\path\to\general_model_registration-2.0.0-py3-none-any.whl"
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

开发虚拟环境准备完成后可直接双击：

```text
run_app.bat
```

或在本目录执行：

```powershell
.\.venv\Scripts\python.exe -m mandible_registration
```

## 使用测试数据运行无界面流程

```powershell
.\.venv\Scripts\python.exe -m mandible_registration `
  --dataset-dir "C:\path\to\six-stl-dataset" `
  --output-dir ".\outputs"
```

## 三维查看、阶段彩虹图和测量

软件内部统一使用浅色主题（主界面、文件浏览器、用途分配窗口、下拉框和查看器侧栏），不再混用系统深色背景与深色文字。Windows 系统主题不会被修改，三维画布仍使用深色背景。

配准完成后点击“颌骨对比 / 测量”。无需重新配准也可点击“打开已有结果”，选择某次结果目录内的 `project.json`，再点击“颌骨对比 / 测量”。

### 阶段配准彩虹图

流程图粗线通过 `auto_alignment.integration.review` 公共接口打开通用配准查看器：浅灰三维背景、正交投影、固定世界光源下的模型旋转、滚轮缩放和中键平移；提供彩虹图、固定模型、配准后移动模型、双色叠加四种模式，正负临界值可调整，名义区间默认为 ±0.05 mm。支持点击局部平均偏差标注、调整半径、删除及清空；标注自动保存在各阶段自己的 `viewer_annotations.json` 中。

这些图显示配准后移动模型相对固定模型的有符号表面偏差，符号取决于参考表面法向；它不是同一解剖点的运动距离。全牙列中的牙根和上颌等非重叠区域也会参与着色，不能将整张彩虹图当作下颌牙冠配准质量。颌骨运动和跨骨距离/角度仍使用下面的专用查看器。历史项目缺少阶段适配文件时可自动补建，仅创建查看器索引，不重做配准或修改模型。

### 颌骨对比与测量

三维窗口使用 VTK 9.6.2 和 PySide6。主界面内打开时复用当前进程和查看窗口，关闭查看窗口只是隐藏，再次打开会保留手动测量；退出整个软件前仍需导出测量。命令行也可独立打开。默认只读取两个颌骨，其余口扫和全牙列在勾选或切换检查模式时按需读取。查看专用 STL 读取不重复执行配准清理，仍校验文件 SHA-256，不降低模型精度。开发环境已经包含这些依赖，新环境请按 `pyproject.toml` 安装。

- **模型显隐**：常规查看提供八项：两次上颌口扫、两次下颌口扫、全牙列.1、全牙列.2和两个位置的颌骨。选中列表项可调整透明度和单色，默认仅显示两个颌骨。颌骨对比窗口不再提供彩虹图，配准彩虹图仍从主流程的三条粗线打开。
- **CT 牙列**：“只看 CT 配准”只显示全牙列.1与下颌口扫.1，用于复核 T_CT；该模式不允许骨间取点，并暂时隐藏已有骨间测量图层。返回“只看下颌骨”后，常规八模型列表恢复，全牙列默认隐藏但可手动勾选。
- **坐标一致性**：导入的全牙列和颌骨必须是同一次 CT 分割导出的原始坐标文件。不要把已单独配准到口扫的 `aligned_current.stl` 作为全牙列输入，否则牙列与颌骨的原始相对关系已丢失。程序会在配准前用包围盒交叠与中心间距作保守检查，明显不一致时停止矩阵传递；打开旧结果时也会明确告警。显示的模型统一在上颌口扫.1坐标系。全牙列.1是按下颌完成定位的完整 CT 牙列；全牙列.2是把同一个完整文件整体应用下颌位姿矩阵后的辅助显示。若文件同时包含上颌牙，显示中的 CT 上颌也会一起移动，因此不能把它解释为真实的第二位置上颌牙列。缺失或哈希不匹配的模型会告警并跳过，不会用其他原始模型代替；旧结果没有 `ct_dentition_T1.stl` 时会在内存中由全牙列.1和 `T_DELTA` 补出，不修改旧项目。
- **标记与骨间距离**：不再提供取点模型选择框。选择“骨间距离”后点击任一下颌骨，首点自动确定该骨，第二点自动锁定另一次下颌骨；两个端点不能落在同一个骨上。结果是手选两点的三维直线距离，不是表面路径，也不会自动寻找对应解剖点。单点标记同样只能落在两个下颌骨上，记录注明 T0/T1。
- **骨间角度**：在任一次下颌骨上连续取 P1、P2，随后程序自动锁定另一次骨面取 P3、P4，比较 P1→P2 与 P3→P4 两条有向线的 0–180° 三维夹角。两次须按相同解剖方向取点；零长度线段会被拒绝。不再使用单一模型上的三点夹角。默认浏览模式不生成测量点。
- **取点与视图**：左键拖动旋转、中键平移、滚轮缩放；沿 X/Y/Z 轴查看仅代表坐标方向，不预设解剖方位。开始测量会恢复两个下颌骨显示；口扫、CT 牙列和标记图层永远不参与取点。首点命中靠近相机的骨面，后续按测量步骤锁定骨面，即使另一骨挡在前面。面板提示当前需要哪一次骨面；如果手动隐藏或完全透明化当前需要的骨面，会暂停取点并提示恢复显示，不会取另一骨的点代替。端点用半径固定为 0.1 mm、沿所在面片切平面放置的圆片表示，不使用球体或端点名称；三维标签只显示数值和单位，内部测量 ID 仍保留在导出记录中。
- **点击响应修复**：Qt 层识别短按并在 VTK 结束相机交互后触发表面取点，不再依赖可能被相机交互器吞掉的 VTK 松开事件。坐标由当前画布的实际像素尺寸换算，兼容高 DPI；拖动旋转不会生成标记。`scripts/check_measurement_clicks.py` 通过真正的 Qt 鼠标事件测试距离、角度、拖动和浏览模式，而不是直接调用取点函数。
- **保存**：支持撤销、删除选中记录、清空和导出 JSON，记录数值、单位、每点坐标/模型/三角面编号及两个下颌骨的哈希。测量 JSON 的 schema_version 为 2，骨间角度明确记录两条线的端点索引及定义。标记和连线属于置顶测量图层，不被骨面遮住，也不随模型显隐一起隐藏。测量不会自动保存，也不写入 STL；关闭前请导出。导出只创建新文件，不覆盖配准矩阵、项目或已有记录。目前不支持重新导入测量 JSON。

侧栏支持滚动，窗口高度较小时，测量管理和导出按钮位于侧栏下方。

### T_CT 配准重点面选区

导入“下颌口扫.1”或“全牙列”后，可点击各自节点右侧的“选区”按钮。每个模型只编辑一个“配准区”，所选面片会通过 `general-model-registration==2.0.0` 的公共接口作为 T_CT 重点采样面。旧版 A/B 选区会无损合并成这个单一区域。选区不会裁掉其余模型，未选择时仍保持原有全自动配准。选区与模型路径、SHA-256和三角面数量绑定，换文件后不会误用旧选区，并随新项目归档到 `project.json` 的 `registration_selections`。主流程图中已有有效记录的按钮显示为绿色“已选”，点击仍可重新编辑。只有“保存并关闭”会提交本次编辑；标题栏关闭或“取消并关闭”会返回主界面且保持原选区不变，空选区不会阻止退出。

该功能只影响第一阶段的全牙列→下颌口扫.1；不会传入上颌对齐或下颌位姿变化阶段。选择有效面片后即可保存。它能提高已知稳定牙面的采样权重，但不会绕过残差、覆盖率和两次独立结果一致性检查。

### 髁突选区与自动中心位移

在主界面导入“颌骨”后，点击节点右侧的“选区”按钮即可使用通用配准项目的套索编辑器。右侧面板用并排的“左侧髁突 / 右侧髁突”按钮明确当前编辑侧；左键圈选，Ctrl + 左键取消，中键旋转、Alt + 中键平移、右键短按菜单、滚轮缩放，并继承通用项目的异步选区与快速渲染优化。一次只编辑一侧，两侧不可重叠。允许只保存单侧，点击“保存并关闭”时会弹窗确认，未选择侧不会生成分析数据；直接取消关闭不要求选择任何一侧。摘要会持续显示当前编辑侧和两侧面片数。这里的选区只用于测量，不用于配准，也不删除或修改原始 STL。仍需六个 STL 齐全才能开始配准。

- **中心定义**：所选三角面片的面积加权质心，不是简单顶点平均、球拟合中心或解剖旋转中心；中心可能位于骨内部，结果受选区范围影响。
- **保存**：选区自动写入 `outputs/condyle_selections`，与原始颌骨文件哈希绑定。新配准结果会在 `project.json` 中归档选区快照。旧结果也可补选：打开旧项目，导入的颌骨路径有效时点击选区，再回到测量窗口即可刷新，无需重做配准。
- **位移**：原始 CT 中心分别乘 `T_MANDIBLE_T0` 和 `T_MANDIBLE_T1`，得到两位置中心；显示直线位移、带符号的 ΔX/ΔY/ΔZ、位移向量与 +X/+Y/+Z 的夹角。零位移时方向和方向角不定义。
- **角度**：单独显示整个颌骨的刚体总旋转角（0–180°）；同一刚体的两侧共享这一旋转，不能解释为单个髁突的独立旋转。XYZ 是上颌口扫.1 的坐标轴，不预设为解剖学左右、前后、上下。
- **导出**：即使没有手动测量，也可以导出含左右中心、位移、方向角、总旋转角、选区定义和原始文件哈希的测量 JSON。选区变化后重新打开测量窗口会重新计算自动结果，手动测量不变。

```powershell
.\.venv\Scripts\python.exe -m mandible_registration --view-project ".\outputs\某次结果\project.json"
.\.venv\Scripts\python.exe -m pytest
```
